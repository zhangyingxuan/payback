# 发布流程

> 最后验证：2026-10-13

两类发布：内部 npm 包发布（lerna）与服务上线（webhook 自动部署 / docker）。

## 一、lerna 包发布

pay-back-core 等包发布到 taobao registry，独立版本（independent）：

```bash
pnpm version            # lerna version --no-commit-hooks：交互选版本、打 tag
pnpm publish:beta       # --force-publish --dist-tag=beta --skip-git
pnpm publish:latest     # --force-publish --skip-git
```

注意：`--force-publish` 会全量重发所有变更包；发布前确保 `pnpm build` 通过（nx 缓存命中不代表产物正确，可 `pnpm clean:dist` 后全量构建验证）。

## 二、服务上线（自动，主链路）

前提：服务器已配 Gitee webhook → `POST /webhook`（webhook-server :3002）。

1. push 代码到目标分支（env `TARGET_BRANCH`）
2. Gitee 侧完成构建（本地 BUILD_CMD 已注释，构建不在服务器执行）
3. webhook-server 验签 → 命中 `WATCH_DIRS` → 服务器 `git pull`
4. 企微收到部署结果 `notice` 通知——**没收到通知即部署链路异常**

上线检查清单：
- [ ] 部署通知送达
- [ ] `GET /blowsysun/test` 返回正常
- [ ] `fetchDataHealth` 当日数据完备
- [ ] 登录、盯盘页、复盘页可打开
- 回滚：在 Gitee 回退 commit 并 push 目标分支（触发同一 git pull 链路）

## 三、Docker 部署

```bash
docker-compose up -d                                  # client(8080)+server(3000)+mysql
docker-compose -f docker-compose-consul.yml up -d     # Consul（推送依赖）
```

顺序：mysql → push-server（注册）→ server（发现）→ client。
push-server 也可用 PM2：`cd packages/push-server && pm2 start ecosystem.config.js`。

## 四、发版联动检查

| 变更类型 | 上线前动作 |
|----------|-----------|
| entity 改动 | dev 库验证 synchronize ALTER 结果（防锁表/丢数据） |
| scheduler config.ts 改动 | 重启后 `GET /pay-back/initSchedulerTask` 或看注册日志确认任务数 |
| core 改动 | 先 `pnpm build`（server 用 lib 产物，client 用源码 alias，两端都回归） |
| env 新增 key | 更新 `.env.dev/.env.prod` 模板与 [环境配置](../04-技术方案/环境配置.md) |
