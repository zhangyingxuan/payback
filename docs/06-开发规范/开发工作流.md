# 开发工作流

> 最后验证：2026-10-13

## 环境准备

```bash
# Node >= 22，pnpm 必需（workspace:* 协议）
pnpm install
cd packages/core && pnpm build     # 首次需先构建共享库（server 按 lib 引用）
```

## 日常开发

| 命令（根目录） | 作用 |
|----------------|------|
| `pnpm start:server` | 后端 dev（nest start --watch，NODE_ENV 选 .env.dev/.env.prod） |
| `pnpm start:client` | 前端 dev（vite --mode test） |
| `pnpm start:pushServer` / `start:webhookServer` / `start:wxPusher` | 各微服务 |
| `pnpm start:all` | lerna 并行全启 |
| `pnpm build` | lerna run build（nx 保证 core 先构建） |
| `pnpm clean` / `clean:dist` / `clean:cache` | 清理 |

分支现状：日常开发在 `master`，PR 目标分支历史上用过 `1.0.4`（版本分支流）——新 PR 先与负责人确认目标分支。

## 代码检查现状（重要）

- ESLint/Prettier 配置**只在 packages/client**（.eslintrc.js：vue3-essential + @typescript-eslint；.prettierrc.js：printWidth 80、单引号、semi）。根目录无 lint 配置。
- 根 lint-staged 配置存在，husky pre-commit 文件也存在，但其中 `npx lint-staged` **已被注释**——当前提交不做任何检查。
- 结论：质量门禁靠自觉 + client `pnpm build` 的 vue-tsc 类型检查。恢复钩子是待办项。
- client lint 命令：`cd packages/client && pnpm lint`（eslint --fix + prettier --write）。

## 提交规范

现状中英混杂、存在 "Update xxx" 低信息提交。约定向 Conventional Commits 靠拢（近期提交已遵循）：

```
feat(scope): 新功能描述        例: feat: 早盘9:25推送新股与集合竞价涨停到飞书卡片
fix(scope): 缺陷修复           例: fix(charts): stop checkbox click from toggling board collapse
docs / refactor / chore
```

scope 用模块名（charts/client/server/push…）。禁止纯 "update"。

## 敏感信息红线

- `.env.dev` 曾泄露真实主机信息（后用占位符脱敏，commit cea9893）。任何主机地址、token、同花顺票据（user.ticket）不得提交。
- 知识库与代码中不得写入密钥值，只写 key 名。
