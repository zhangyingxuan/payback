# 聊天历史渐进加载实施计划

**目标：** 会话摘要分页、正文按需加载、全历史搜索；保留本地失败消息及生成中的会话。

**范围：** `payback-agent` 的 memory/serve、存储及接口测试；`payback` 的 agent API、chat store、chat 页面、回归测试与协作文档。不提交代码、不新增依赖、不改表。

**实施裁定：** 旧表没有时间列，使用最后消息递增 ID 作为游标与远端排序键，字符串传输避免 BIGINT 精度损失；不伪造历史日期。保留旧 `GET /sessions`，新增摘要查询模式及详情 GET。按现有工作区实施，保留已有改动。

- [x] 后端：先测后写摘要分页、标题/正文搜索、详情、参数校验、旧接口兼容。摘要查询不携带完整正文，无逐会话查询。
- [x] 前端：摘要与正文加载状态分离；首屏 30 条、触底/按钮加载更多、搜索防抖和过期请求取消、详情竞态保护、删除与生成兼容。
- [x] 缓存：普通远端正文不落 localStorage；保留旧记录、未完成/失败消息；最多保留 5 个可重新获取的正文缓存，生成中和未同步内容不淘汰。
- [x] 验证：接口/存储测试、前端 store/列表回归与类型检查；同步 README 和三项目协作文档，检查临时产物。

**主要边界：** 无历史、恰好一页、正文命中、特殊搜索字符、非法游标、隐藏/删除会话、快速切换、搜索覆盖旧请求、切换时后台生成、本地缓存写入失败。

**实现记录：** 前端 10 项测试与 vue-tsc 通过；Agent 全套 168 项通过，5 项隔离 MySQL 测试缺账号跳过。隔离浏览器模拟 65 条历史，验证首屏仅 30 摘要加 1 正文、触底追加至 60、搜索正文片段及按需读取另一会话；桌面与移动端抽屉已查看。Lerna 构建按依赖启动，但 core 原有 `rm` 脚本在 Windows 不可执行，client 构建被依赖失败阻断；未更改构建配置或安装依赖。
