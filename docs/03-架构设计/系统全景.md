# 系统全景

> 最后验证：2026-10-13

本文描述 payback 主项目的包职责、数据流、端口和部署拓扑；同级 Agent 与 MCP 项目的当前协作关系见 [三项目协作与 AI 复盘](三项目协作与AI复盘.md)。

## 包职责总览

| 包 | npm 名 | 职责 | 技术栈 | 端口 |
|----|--------|------|--------|------|
| packages/client | - | 看盘后台 | Vue 3.5 / Vite 7 / Element Plus / Pinia / ECharts | dev 8888；容器 nginx 8080 |
| packages/server | pay-back-server | 采集调度 + REST API | NestJS 9 / TypeORM 0.3 / MySQL 5.7 | 3000 |
| packages/core | pay-back-core | 共享工具与问财查询语句 | TS + Rollup（产出 cjs/esm/d.ts） | - |
| packages/push-server | - | 快讯/消息推送 | NestJS 微服务（TCP，非 HTTP） | 3001 |
| packages/webhook-server | pay-webhook-server | Gitee webhook 自动部署 | NestJS 9 | 3002 |
| packages/wxPusher | pay-back-wx-pusher | Wechaty 机器人原型（未接入主链路） | wechaty 1.18 | - |

## 服务发现（Consul）

- `docker-compose-consul.yml` 起 consul:1.10.1 dev agent（dc1，宿主 18500→容器 8500，带 UI）。
- push-server 启动时注册服务名 `payBack_pushServer_<env>`；server/webhook-server 启动时 `findService` 解析地址后建立 `@nestjs/microservices` TCP ClientProxy。
- 各服务自带 `portManager.ts`：端口占用时自动换端口（注册与发现因此始终用运行时地址）。

## 部署拓扑

| 方式 | 说明 |
|------|------|
| Docker Compose | client(nginx 8080, 挂 nginx.conf) + server(3000) + MySQL 5.7(3306)，bridge 网络 mysql_bridge；server restart: on-failure |
| 抓取镜像 | 根 dockerfile 基于 `playwright:v1.35.0-jammy`，COPY packages/server，装 firefox |
| PM2 | push-server 用 `ecosystem.config.js` 守护 |
| 自动部署 | webhook-server 收 Gitee push：验签(X-Gitee-Token/Timestamp)→比对 TARGET_BRANCH→WATCH_DIRS 命中→`git pull`→结果推 notice；构建在 Gitee 侧完成 |

## 外部依赖

| 系统 | 用途 | 风险点 |
|------|------|--------|
| 同花顺 10jqka / 问财 iwencai | 行情与选股数据源 | 反爬（hexin-v）、接口按月变动 |
| 财联社 | 快讯源 | push-server 定时 HTTP 拉取 |
| 企微机器人 webhook | 告警/快讯推送 | robotList 配置在 env |
| 飞书 bot webhook | 快讯/早盘卡片推送 | HMAC 签名密钥 |
| Gitee | 代码托管 + webhook 触发部署 | 需配 TOKEN/分支/目录白名单 |
| Consul 1.10.1 | 服务发现 | dev agent 单点 |
