# 业务流程

> 最后验证：2026-10-13

本文描述 PayBack 端到端数据流与交易日时间线。

## 端到端数据流

```
外部数据源                采集层(server)              存储          消费层
─────────                ────────────────          ────          ────────
同花顺 10jqka   ─┐
问财 iwencai    ─┼─Playwright/HTTP─► pay-back 12 个 ─┐
财联社快讯      ─┘        (hexin-v token)  service    ├─► MySQL ─► REST API ─► client 看盘
                                                     │  (11 张表)
                                                     └─► Consul TCP ─► push-server ─► 企微/飞书
```

- 采集入口：`server/src/scheduler-task/config.ts` 动态注册 Cron；也可经 `/pay-back/crawl*` 手动补采。
- 问财查询语句集中维护在 `core/src/config/index.ts`（跌停/炸板/连板/竞价/新股/资金流/板块涨跌等条件串）。
- 反爬：`core/src/utils/hexin-v` 生成同花顺 token；抓取失败重试（`TASK_RETRY_TIME`）并企微告警。
- 推送链：server 经 Consul 发现 `payBack_pushServer_<env>` → TCP 事件（`notice` / `noticeNews` / `pushMorningMessage`）→ push-server 组装 markdown/卡片 → 企微机器人 + 飞书 bot（HMAC 签名）。

## 交易日时间线（Asia/Shanghai）

自 2026-11-12 起，除热榜外所有定时任务（含新闻推送）执行前均校验 core 本地交易日历，周末、公告休市及未核验年份跳过。热榜全年按原 Cron 执行。当前日历覆盖 2026 年，跨年前需补充下一年度公告数据。客户端顶部展示休市状态、下一开市日期或距下一次节假日休市的天数，非节日当天倒计时。

| 时刻 | 动作 |
|------|------|
| 7:00-23:00 每 30 分 | 热榜采集 |
| 7:00-23:00 每 2 分 | 新闻快讯抓取（push-server） |
| 9:05 / 16:00 / 23:00 | 最新概念板块采集 |
| **9:25** | 竞价数据+新股&强势股采集；**集合竞价涨停（按封单量）+新股推送飞书卡片** |
| 11:31 / 15:10 | 大盘市场数据采集 |
| 11:33 / 15:40 | 板块数据采集 |
| 11:36 / 15:35 | 短线数据采集；尾盘后自动加同花顺自选 |
| 11:38 / 15:33 | 竞价数据采集 |
| 11:40 / 15:37 | 新股&强势股采集 |
| 11:41 / 15:32 | 资金数据采集（周一至五），为双图推送预留时间 |
| **15:38** | 校验当日收盘数据后，将复盘全景图、短线涨停梯队图同时推送飞书和企微；长图分段，缺失数据不推送旧图 |

> 精确清单以 `packages/server/src/scheduler-task/config.ts` 为准；改任务必须同步本表与后端技术方案。

## 系统边界

| 我们做 | 我们不做 |
|--------|----------|
| 行情/情绪/板块数据采集存档与展示 | 实盘交易、下单 |
| 快讯与竞价消息推送到企微/飞书 | 荐股或投资建议输出（仅数据陈述） |
| 同花顺自选股同步 | 同花顺账号资产管理 |
| 复盘数据的统计回顾 | 支付收款（商业化仍在调研期，见支付方案调研报告） |

## 异常与补偿

- 采集失败：按 `TASK_RETRY_TIME` 重试，最终失败发企微告警（`utils/schedulerUtil.ts`）。
- 数据完备性：`fetchDataHealth` 检查各表当日数据是否齐。
- 端口占用：各服务启动时 `portManager.ts` 自动换端口。
