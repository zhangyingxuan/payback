# 推送与部署方案

> 最后验证：2026-10-13

覆盖 push-server（消息推送）、webhook-server（自动部署）与 wxPusher（原型）。

## push-server（TCP 微服务，3001）

- **不是 HTTP 服务**：`main.ts` 用 `createMicroservice` 起 TCP `0.0.0.0:3001`，并向 Consul 注册 `payBack_pushServer_<env>`。
- **消息入口**（PushController `@EventPattern`）：
  | 事件 | 来源 | 内容 |
  |------|------|------|
  | `notice` | server / webhook-server | 通用告警文本 |
  | `noticeNews` | server 新闻任务 | 财联社快讯 |
  | `pushMorningMessage` | server 9:25 任务 | 新股 + 集合竞价涨停（按封单量）飞书卡片 |
  | `pushReviewCharts`（请求响应） | server 15:38 任务 | 全景与梯队 SVG 转 PNG，返回各通道是否成功 |
- **出站通道**：企微机器人 webhook（robotList 多群）+ 飞书 bot webhook（HMAC 签名），消息组装为 markdown。
- **自主抓取**：NewsService 定时拉财联社快讯接口，`color === '2'` 判定重要消息再推送。
- **部署**：PM2 `ecosystem.config.js` 守护；端口占用 portManager 自动换。

### 15:38 收盘双图

- server 在交易日北京时间 15:38 执行 `autoPushReviewCharts`（`0 38 15 * * 1-5`），资金采集从 15:45 提前到 15:32，短线仍为 15:35。现有启动流程会注册任务，无需手动调用初始化接口。
- server 的 `PAYBACK_AGENT_URL` 默认为 `http://127.0.0.1:8300`；分容器部署时配置为可达的 Agent 内网地址。调用 `POST /review-charts/YYYY-MM-DD`，经 Agent 串行 MCP worker 查询全景、完整梯队、短线周期并绘图，不调用模型或创建聊天会话。
- 大盘、短线、资金、梯队必须属于指定日期且记录时间不早于 15:00；旧日、午盘、缺失及截断数据拒绝推送。外围指数是最新可用报价，图片保留实际报价时间，不能视为当日收盘价。
- 梯队头部的周期、封板率、涨跌停数以本次短线原始快照为准；晋级率仅接受同日收盘后的派生表记录，未生成或仍为午盘版本时显示“未提供”，不阻断其余有效图表。
- push-server 使用 `@resvg/resvg-js` 原生工作线程转换图片，保持 990 / 1200 像素原宽，每段最多 1600 像素高、2 MiB。长梯队按顺序分图，通道独立执行，图间等待 3.1 秒；15:38 是任务开始时间，生成和发送需要一定时间。
- **push-server 环境变量**：设置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，对应应用开启机器人能力并获批图片上传权限（`im:resource`），令牌经官方接口获取。不要把凭据提交仓库。目标群沿用 `PushService` 已有飞书 webhook 和企微机器人列表。
- **中文字体**：部署主机／容器需安装中文字体，例如 Linux 的 Noto Sans CJK，Windows 可用微软雅黑。无中文字体可能生成缺字图片，必须在目标运行环境验图。安装根工作区依赖时保留 resvg 对应平台的原生可选包。
- Agent 端点与现有聊天接口一致无鉴权，仅在可信本机或受保护内网开放，不对公网直接暴露。
- 沿用 `TASK_RETRY_TIME`（默认 3 次），双图失败间隔 30 秒重试，日志及既有告警通道报告失败；HTTP 状态与业务错误码均须成功。当前进程内逐群、逐图记录已成功回执，重试只发送未成功部分；服务重启、多实例及远端成功但本地未收到回执时仍可能重复，尚未引入持久化去重。
- 验证使用 mock 网络，不实际发送群消息；部署需要同时更新 server、push-server、payback-agent，配置完成并重启后才会生效。

官方接口说明：[飞书自定义机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)、[飞书上传图片](https://open.feishu.cn/document/server-docs/im-v1/image/create)、[企微机器人消息](https://developer.work.weixin.qq.com/document/path/91770)。

## webhook-server（3002）

`POST /webhook` 接收 Gitee push 事件，链路：

1. 校验 `X-Gitee-Token` / `X-Gitee-Timestamp` / `X-Gitee-Event`（仅 push 事件，HMAC 验签 + 时间窗）。
2. 比对 env `TARGET_BRANCH`，非目标分支忽略。
3. 检查变更文件是否命中 `WATCH_DIRS` 白名单目录。
4. `DeployService.deploy()` 执行 `git pull`（构建在 Gitee 侧完成，本地 BUILD_CMD 已注释）。
5. 结果经 `PUSH_SERVER` TCP 事件 `notice` 推企微。

辅助端点：`GET /webhook/generateSignature`（本地生成测试签名）。
排错要点：验签失败查 TOKEN 与时钟；不部署查分支名与 WATCH_DIRS；无通知查 Consul 是否解析到 push-server。

## wxPusher（原型，未接入主链路）

- Wechaty 1.18 + 多 puppet（wechat/wechat4u/whatsapp/oicq/walnut），qrcode-terminal 扫码登录。
