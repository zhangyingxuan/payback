# 推送与部署方案

> 最后验证：2026-10-13

覆盖 push-server（消息推送）、webhook-server（自动部署）与 wxPusher（原型）。

## push-server（TCP 微服务，3001）

- **不是 HTTP 服务**：`main.ts` 用 `createMicroservice` 起 TCP `0.0.0.0:3001`，并向 Consul 注册 `payBack_pushServer_<env>`。
- **消息入口**（PushController `@EventPattern`）：
  | 事件 | 来源 | 内容 |
  |------|------|------|
  | `notice` | server / webhook-server | 通用告警文本 |
  | `noticeNews` | server 新闻任务 | 财联社快讯 |
  | `pushMorningMessage` | server 9:25 任务 | 新股 + 集合竞价涨停（按封单量）飞书卡片 |
- **出站通道**：企微机器人 webhook（robotList 多群）+ 飞书 bot webhook（HMAC 签名），消息组装为 markdown。
- **自主抓取**：NewsService 定时拉财联社快讯接口，`color === '2'` 判定重要消息再推送。
- **部署**：PM2 `ecosystem.config.js` 守护；端口占用 portManager 自动换。

## webhook-server（3002）

`POST /webhook` 接收 Gitee push 事件，链路：

1. 校验 `X-Gitee-Token` / `X-Gitee-Timestamp` / `X-Gitee-Event`（仅 push 事件，HMAC 验签 + 时间窗）。
2. 比对 env `TARGET_BRANCH`，非目标分支忽略。
3. 检查变更文件是否命中 `WATCH_DIRS` 白名单目录。
4. `DeployService.deploy()` 执行 `git pull`（构建在 Gitee 侧完成，本地 BUILD_CMD 已注释）。
5. 结果经 `PUSH_SERVER` TCP 事件 `notice` 推企微。

辅助端点：`GET /webhook/generateSignature`（本地生成测试签名）。
排错要点：验签失败查 TOKEN 与时钟；不部署查分支名与 WATCH_DIRS；无通知查 Consul 是否解析到 push-server。

## wxPusher（原型，未接入主链路）

- Wechaty 1.18 + 多 puppet（wechat/wechat4u/whatsapp/oicq/walnut），qrcode-terminal 扫码登录。
- `utils/ding-dong-bot.ts` 为官方 starter 拷贝（onScan/onLogin/onMessage），有独立 dockerfile。
- 结论：实验性质，改动不影响 server/client；勿在此基础上加业务逻辑，先与负责人确认方向。
