# 环境配置

> 最后验证：2026-11-12

各服务端口、环境变量 key 清单（不含值）与启动方式。

完整发布、验证和回滚见[项目部署操作手册](项目部署操作手册.md)。以下是源码配置约定，不能把已有 Docker 文件视为已验证的生产方案。

## 端口速查

| 服务 | 端口 | 说明 |
|------|------|------|
| client dev | 8888（VITE_PORT） | vite dev server |
| client 容器 | 8080 | nginx，挂 nginx.conf |
| server | 3000 | 全局前缀 /blowsysun，nginx 反代同名 |
| push-server | 3001 | TCP 微服务，非 HTTP |
| webhook-server | 3002（APP_PORT 可覆盖） | HTTP |
| MySQL | 3306 | 5.7 |
| Consul UI/API | 宿主 18500 → 容器 8500 | dev agent |
| payback-agent | 默认 127.0.0.1:8300 | HTTP/SSE，无内建鉴权 |
| payback-mcp | 无 | Agent 按需启动的 stdio 子进程 |

> server 使用 portManager，生产应确保 3000 空闲并核对实际监听与注册端口。push-server 固定监听 TCP 3001，不会自动换端口；仅更改 APP_PORT 不会改变其监听。

## 环境变量（key 名清单，值放各机 .env，禁止提交）

**packages/server**：`.env.dev` / `.env.prod`（NODE_ENV 选择）
`DDD_HOST` `DDD_PORT` `DDD_USER` `DDD_PD`(base64) `DDD_NAME`（MySQL）、`CONSUL_HOST` `CONSUL_PORT`、`APP_NAME` `APP_HOST` `APP_PORT`、`TASK_RETRY_TIME`

另有 `DB_SYNCHRONIZE`（生产/存量库建议 false，避免自动变更结构）、`PAYBACK_AGENT_URL`（默认 `http://127.0.0.1:8300`，收盘双图使用）。`NODE_ENV` 显式设 dev 或 prod，避免查找错误的 Consul 服务名。

**packages/client**：`.env` / `.env.development` / `.env.test` / `.env.production`
`VITE_PORT` `VITE_PUBLIC_PATH` `VITE_ROUTER_HISTORY` `VITE_BASE_API` `VITE_BASE_API_THS` `VITE_BASE_API_THS_DQ` `VITE_BASE_API_THS_NEWS`；prod 另有 `VITE_CDN` `VITE_COMPRESSION`

**packages/webhook-server**：Gitee `TOKEN`、`TARGET_BRANCH`、`WATCH_DIRS`、`APP_PORT`、Consul 相关
**packages/push-server**：企微 robotList webhook、飞书 bot webhook 与签名密钥、Consul 相关

飞书图片上传需 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 和应用 `im:resource` 权限；目标群仍需核对 PushService 既有机器人配置。运行环境安装中文字体并保留 resvg 对应平台原生包。

**payback-agent**：根 `.env`，模板见同级仓库 `.env.example`。gateway 模式为 `AGENT_LLM_BASE_URL/API_KEY/MODEL`；codex 模式为 `AGENT_LLM_BACKEND=codex`、可选 `AGENT_CODEX_COMMAND/MODEL`，由服务账户完成 CLI 认证。`PAYBACK_MCP_DIR` 默认同级 payback-mcp，`PAYBACK_MCP_COMMAND` 默认 uv。记忆库使用独立可写的 `AGENT_MEMORY_MYSQL_HOST/PORT/USER/PASSWORD/NAME`。

**payback-mcp**：根 `.env`；`AGENT_MYSQL_HOST/PORT/USER/PASSWORD/NAME` 使用只读行情账号。离线构建专用 `BUILD_MYSQL_USER/PASSWORD` 不用于在线写库；可选行情凭据为 `FUYAO_API_KEY`、`TWELVE_DATA_API_KEY`。

Agent 的 MySQL 记忆表和 `data/daily_reports/` 都需备份/持久化。容器/不同主机之间不得沿用 127.0.0.1 作为对端地址。生产 Nginx 必须另配 `/agentApi/` 去前缀、SSE 禁缓冲与访问控制，Vite 的 `VITE_BASE_API_AGENT` 仅控制开发代理。

历史教训：`.env.dev` 曾被误提交，后以占位符脱敏（commit cea9893）——新增 env 文件务必检查 gitignore。

## 本地启动

```bash
pnpm install                # 根目录，Node >= 22
docker-compose -f docker-compose-consul.yml up -d   # 需要 Consul 时
# 先确保 MySQL、Consul 可达；以下应用命令各自在独立终端运行。
CONSUL_HOST=127.0.0.1 CONSUL_PORT=18500 pnpm start:pushServer
# 同级 payback-agent 目录执行 uv sync --frozen 后运行 uv run --frozen payback-agent --serve。
pnpm start:server           # 后端 3000，发现已注册的推送服务
pnpm start:client           # 前端 8888（--mode test）
```

server 启动时发现 push-server 的异常未被吞掉，缺 Consul 或服务未注册可能直接导致启动失败。需先起 Consul，再起 push-server（注册），后起 server（发现）。本机推送配置曾指向无法解析的 2c2g，已用进程环境覆盖为本地地址；生产需配置实际可达地址。

## Docker 编排

- `docker-compose.yml` 仅含 client/server/mysql，缺推送、Agent/MCP 及完整服务就绪与网络配置。
- server Dockerfile 仍为 Node 16/npm，与现有 Node >=22/pnpm workspace 不一致；客户端文件名大小写、Nginx 挂载位置、静态目录与跨容器代理也需修正。
- 根 Playwright Dockerfile 未适配当前完整发布链。差距和单机部署建议见[项目部署操作手册](项目部署操作手册.md)，不以 compose up 成功作为三仓上线完成证明。

## 生产域名线索

dev 的 `VITE_BASE_API` 之一指向 blowsysun.top；服务器经 nginx 反代 `/blowsysun` → server:3000、静态资源 → client 容器。具体机器地址见运维保管的 .env，不入库。
