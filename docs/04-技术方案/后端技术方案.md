# 后端技术方案

> 最后验证：2026-10-13

packages/server：NestJS 9 采集与 API 主服务，端口 3000，全局前缀 `/blowsysun`。

## 模块结构

| 模块 | 内容 |
|------|------|
| pay-back/ | 核心：controller(pay-back / system-config / ths-trade) + 12 个 service（funds/market/plate/shortTerm/specialStock/hotList/latestConceptPlate/review/systemConfig/ths/qyWechatNotice/apiTest）+ utils（playWrightUtil、tradeDateUtil、dataHealthUtil…） |
| auth/ | JWT + passport 登录，svg-captcha 验证码 |
| article/ | 文章 CRUD |
| users/ | 用户查询 service（无 controller） |
| scheduler-task/ | 动态 Cron 调度 + config.ts 任务清单 |
| consul/ | 注册/发现 + PUSH_SERVER TCP ClientProxy 全局注入 |
| filters/ middleware/ decorator/ utils/ | 异常过滤、日志、`@Public()`、abortFetch、portManager |

## 定时任务机制（重点）

### 休市过滤（2026-11-12）

- 日历由 `core/src/calendar/data/2026.ts` 维护，保存交易所公告、核验日期和包含首尾的休市区间；目前仅核验 2026 年。新年度增加数据文件后加入 `tradingCalendars`，重建 core 和前后端。
- `SchedulerTaskService` 每次触发按上海日期调用 core `getTradingDayInfo`，默认仅 `open` 执行。热榜在 config.ts 显式设置 `tradingDaysOnly: false`；新闻启动注册和开关注册均受过滤。
- 周末及公告休市跳过；未覆盖年份返回 `unknown`，跳过且每个服务实例每天记录一次警告。一次性任务即使跳过也按原有规则删除，手动采集接口不受影响。
- `getNextTradingDay` 严格查询下一交易日，遇到未知年份返回 undefined；共享函数不发网络请求、不访问数据库。
- 验证：通过 Lerna 构建 core 后运行 `pnpm --filter pay-back-core test`；server 运行 `pnpm test -- --runInBand scheduler-task.service.spec.ts`。

- 静态 `@Cron` 全部已注释废弃。**唯一正确姿势**：在 `scheduler-task/config.ts` 登记任务，由 main.ts 启动时 `initSchedulerTask()` 经 SchedulerTaskService 动态注册 CronJob。
- 特性：时区 Asia/Shanghai、防重入锁、一次性任务执行后自动删除、HTTP 端点 `/pay-back/initSchedulerTask` 可重载。
- 失败处理：`utils/schedulerUtil.ts` 按 env `TASK_RETRY_TIME` 重试，最终失败走 qyWechatNotice 企微告警。
- 收盘双图：资金晚盘采集提前至 15:32，短线保持 15:35，`ReviewChartsService` 在交易日 15:38 调用 Agent 绘图并经 push-server 同时发飞书、企微；失败间隔 30 秒重试并等待重试完成，避免任务锁提前释放。重试复用同日快照，push-server 按通道和分图在进程内去重；配置与边界见 [推送与部署方案](推送与部署方案.md)。
- 时刻表见 [业务流程](../02-业务梳理/业务流程.md)，改任务必须同步该表。

## 数据爬取链路

1. **问财 iwencai**：查询语句集中维护在 `core/src/config/index.ts`（跌停/炸板/连板/竞价/新股/资金流/板块条件串）→ HTTP 抓取解析入库。
2. **同花顺页面**：Playwright（容器内 1.35 + firefox）操作，`hexin-v` 本地生成反爬 token；ths-trade 模块实现自选股/板块增删（含按中文名）。
3. **交易日判断**：tradeDateUtil 决定采集与推送是否执行。
4. **数据完备性**：dataHealthUtil 支撑 `fetchDataHealth` 端点。

## 认证与守卫

- 全局 `JwtAuthGuard`（APP_GUARD），免登录接口必须标 `@Public()`。
- 限流：express-rate-limit；缓存：cache-manager。

## 与 push-server 通信

- 启动时 Consul `findService('payBack_pushServer_<env>')` → 建立 TCP ClientProxy（全局 `PUSH_SERVER` token）。
- 事件：`notice`、`noticeNews`、`pushMorningMessage`（payload 为自定义 JSON，无 HTTP 契约）。

## 其他注意

- TypeORM `synchronize: true`：改 entity 即改表，无迁移机制；存量字段兼容要人工评估。
- MySQL 驱动为 legacy `mysql@2.18.1`，不要按 mysql2 API 写代码。
- Swagger 依赖与 `ApiProperty` 注解在用，但 main.ts 未 `SwaggerModule.setup`——无文档端点。
- 端口占用时 portManager 自动换端口。
